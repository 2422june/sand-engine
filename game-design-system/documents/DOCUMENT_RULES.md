# Document Writing Rules v0.1

Document는 **이번 게임의 원본 기획서**다. Rule Book과 Blue Print가 이 문서를 해석·구현한다.

이 파일의 규칙은 **충족하면 좋은 조건**이며, 작가의 작성을 막는 제한이 아니다.
즉, 빠진 항목이 있어도 Document는 유효하고, 형식이 달라도 의미가 살아 있으면 받아들인다.

## 원칙

- Document의 1순위는 **아이디어 보존**이다. 문장력보다 의도, 분위기, 장면, 규칙이 더 중요하다.
- 완전히 정리되지 않은 메모, 단편 문장, 대사, 키워드만 있어도 된다.
- 모호함은 허용한다. 다만 중요한 선택, 감정, 규칙은 드러날수록 Blue Print 품질이 좋아진다.
- 기존 섹션 구조를 안 지켜도 된다. 필요한 경우 자유롭게 새 섹션을 추가한다.
- 이미지, 사운드, 레퍼런스 링크, 파일 경로는 일부만 적혀 있어도 된다.

## 권장 포함 항목

아래는 "있으면 좋은" 조건이다. 전부 채워야 하는 체크리스트가 아니다.

### 1. 게임 정체

- 게임 제목 또는 가제
- 장르 / 분위기 / 핵심 감정
- 플레이어가 반복해서 하게 될 핵심 행동

### 2. 시나리오/상황

- 세계관, 배경, 도입부, 주요 사건
- 캐릭터, 적, NPC, 세력, 장소
- 작가가 꼭 살리고 싶은 장면이나 대사

### 3. 플레이 규칙

- 승리 / 실패 / 진행 조건
- 선택지, 전투, 퍼즐, 탐험, 성장 등 핵심 시스템 메모
- 플레이어가 알아야 하는 위험과 보상

### 4. 게임 화면

- 어떤 화면이 필요한지
- 각 화면에서 플레이어가 무엇을 보고 무엇을 누르는지
- HUD, 메뉴, 인벤토리, 대화창, 로그, 미니맵 등 필요한 UI 요소
- 화면 전환 흐름 또는 연출 포인트

예시:
- 타이틀 화면
- 인게임 메인 화면
- 대화/선택지 화면
- 게임오버/엔딩 화면

### 5. 이미지/사운드 소스

- 사용할 이미지, 사운드, 음악, 폰트, 레퍼런스 영상/링크
- 파일 경로가 있으면 경로를 적고, 아직 없으면 필요한 소스 종류만 적어도 된다
- 임시/확정 여부, 직접 제작/외부 소스 여부를 같이 적으면 좋다

권장 형식 예시:
- 이미지:
  - `assets/ui/title-bg.png` — 타이틀 배경, 임시
- 사운드:
  - `assets/audio/radio-noise.wav` — 무전 잡음, 필수

### 6. 게임 흐름도

- 시작부터 종료까지 플레이 흐름
- 분기, 반복, 체크포인트, 루프, 엔딩 조건
- 텍스트 목록, 화살표, 의사코드, ASCII 다이어그램 어느 형식이든 가능

예시:
`타이틀 -> 도입부 -> 탐험 허브 -> 이벤트 분기 -> 보스/결말 -> 엔딩`

## 권장 작성 방식

- 길게 써도 되고 짧게 써도 된다.
- 완성본처럼 써도 되고, 메모 조각처럼 쌓아도 된다.
- 섹션 순서는 자유다.
- 같은 내용이 중복되어도 괜찮다. 해석 단계에서 정리하면 된다.

## Blue Print 변환 관점

Document가 아래 정보를 많이 줄수록 Blue Print가 더 정확해진다.

- 플레이어가 실제로 보게 될 화면
- 사용하는 리소스의 경로/종류
- 시작, 분기, 종료를 잇는 흐름
- 상태 변화의 원인과 결과
- 반드시 지켜야 하는 분위기와 장면

## 비제한 선언

이 규칙 파일은 **금지 규정집이 아니다**.

- 섹션이 빠져도 된다
- 문장 대신 키워드만 있어도 된다
- 순서가 뒤섞여도 된다
- 나중에 다시 덧붙여도 된다

핵심은 "작성자가 막히지 않고 남길 수 있어야 한다"는 점이다.
